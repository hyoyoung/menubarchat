# 대화 기능 스펙

## Purpose

모델과 주고받는 대화. 토큰 단위 실시간 스트리밍, 추론 과정 표시, 중단.

## Requirements

### Requirement: 메시지 전송
Enter(또는 전송 버튼)로 초안을 전송하되 빈 입력은 무시한다. 초안은
비워지고 사용자 메시지는 즉시 오른쪽 정렬 말풍선으로 나타난다. 응답
스트리밍 중 Enter는 초안을 대기열(최대 1개)에 넣고 초안을 비운다. 대기
중 다시 Enter를 누르면 무시하고 초안을 유지한다. 대기 메시지는 스트림이
끝나는 즉시(완료·중단 무관) 자동으로 전송되며, 대기 목록이 화면에
표시된다. 각 대기 항목은 즉시 전송(현재 응답을 끊고 바로 전송), 삭제,
초안 되돌리기로 조작할 수 있고 전체 해제도 할 수 있다.

#### Scenario: 스트리밍 중 전송
- **WHEN** 응답이 스트리밍되는 중 사용자가 Enter를 누르면
- **THEN** 메시지가 대기열에 들어가고 스트림 종료 직후 자동 전송된다

#### Scenario: 대기 중 추가 입력
- **WHEN** 대기 메시지가 있는 상태에서 다시 Enter를 누르면
- **THEN** 무시되고 초안은 그대로 남는다

#### Scenario: 대기 메시지 즉시 전송
- **WHEN** 대기 항목에서 즉시 전송을 선택하면
- **THEN** 현재 응답이 중단되고 대기 메시지가 바로 전송된다

### Requirement: 스트리밍 표시
SSE로 응답을 스트리밍한다. `reasoning_content` 델타는 답변 위의 작은
글씨 회색 말풍선에, `content` 델타는 기본 크기 답변 말풍선에 덧붙이며
도착하는 즉시 반영한다. 최신 메시지로의 자동 스크롤은 팔로우 상태에서만
일어난다: 사용자가 위로 스크롤하면 팔로우가 끊겨 스크롤 위치가 유지되고,
뷰포트가 맨 아래에 도달하거나 사용자가 메시지를 전송하면 재개된다.
팔로우가 끊긴 동안에만 기록 하단에 떠 있는 점프 버튼이 표시되며 누르면
즉시 맨 아래로 이동해 팔로우를 재개한다. 스트림은 `[DONE]` 데이터 라인에서
끝난다.

#### Scenario: 추론과 답변 분리 표시
- **WHEN** 델타에 `reasoning_content`와 `content`가 번갈아 도착하면
- **THEN** 추론은 작은 글씨 회색 말풍선에, 답변은 기본 말풍선에 즉시 덧붙여진다

#### Scenario: 스크롤 위치 유지
- **WHEN** 스트리밍 중 사용자가 위로 스크롤하면
- **THEN** 새 델타가 도착해도 화면은 끌려가지 않고 점프 버튼이 나타난다

#### Scenario: 점프 버튼으로 복귀
- **WHEN** 팔로우가 끊긴 상태에서 점프 버튼을 누르면
- **THEN** 즉시 맨 아래로 이동하고 자동 스크롤이 재개된다

### Requirement: 토큰 소비량 표시
스트림 마지막 청크의 `usage`가 도착하면 해당 답변 아래에 "↑<입력 토큰>
↓<출력 토큰>" 작은 캡션을 표시한다. `usage`가 없으면(오류, 중단) 표시하지
않는다.

#### Scenario: 토큰 소비량 표시
- **WHEN** 마지막 청크에 `usage`가 도착하면
- **THEN** 답변 아래에 "↑<입력 토큰> ↓<출력 토큰>" 캡션이 표시된다

### Requirement: 추론 말풍선 접기
추론이 5줄 이하면 전체를, 넘으면 앞 5줄만 표시하고 말풍선 맨 아래에
More/Less 라벨(이탤릭)을 둔다. 라벨에는 바로 앞 사용자 메시지의 첨부
ID를 함께 표시한다. 클릭할 때마다
펼침/접힘이 토글되고, 펼침 상태는 재시작 시 유지되지 않는다.

#### Scenario: 긴 추론 접기
- **WHEN** 추론이 5줄을 초과하면
- **THEN** 앞 5줄만 표시되고 More/Less 라벨 클릭으로 펼침/접힘이 토글된다

### Requirement: 중단
중단 버튼을 클릭하면 진행 중인 스트림을 취소하고, 지금까지 받은 부분
텍스트는 오류 없이 유지한다.

#### Scenario: 스트리밍 중단
- **WHEN** 응답 스트리밍 중 중단 버튼을 클릭하면
- **THEN** 스트림이 취소되고 지금까지 받은 부분 텍스트가 그대로 남는다

### Requirement: 메시지 복사
어시스턴트 답변 말풍선 하단 오른쪽에 항상 작은 복사 아이콘을 표시한다.
사용자 말풍선은 마우스를 올렸을 때만 오른쪽 아래 모서리에 겹쳐 표시한다
(공간을 차지하지 않아 말풍선 크기는 변하지 않는다). 클릭하면 해당 메시지
전문이 클립보드에 복사되고 1초간 체크 아이콘으로 바뀐다. 추론 말풍선에는
없다.

#### Scenario: 답변 복사
- **WHEN** 어시스턴트 말풍선의 복사 아이콘을 클릭하면
- **THEN** 메시지 전문이 클립보드에 복사되고 아이콘이 1초간 체크로 바뀐다

### Requirement: 기본 지시문
사용자 메시지가 URL 하나뿐이거나 긴 붙여넣기(10줄 초과)면, 그 메시지가
마지막 메시지인 요청의 `content` 끝에 설정의 지시문을 `[Instruction:
<지시문> — unless the user already asked something specific above]` 형태로
덧붙인다. 지시문이 비어 있으면 덧붙이지 않고, 말풍선 표시는 원문
그대로다. 기본값과 편집은 설정 스펙을 따른다.

#### Scenario: URL만 입력
- **WHEN** 사용자가 URL만 붙여넣어 보내면
- **THEN** 기본 지시문이 적용되어 모델이 요약으로 답한다

#### Scenario: 사용자 지시와 함께 붙여넣기
- **WHEN** 사용자가 자신의 지시(예: "원인 찾아줘")와 함께 긴 텍스트를 붙여넣으면
- **THEN** 기본 지시문보다 사용자 지시가 우선 적용된다

### Requirement: 지우기
휴지통 버튼을 클릭하면 대화를 모두 지운다.

#### Scenario: 대화 지우기
- **WHEN** 휴지통 버튼을 클릭하면
- **THEN** 대화의 모든 메시지가 사라진다

### Requirement: 오류 표시
2xx가 아닌 HTTP 응답은 "Error: HTTP <코드>: <본문(잘림)>" 어시스턴트
말풍선으로 표시한다. 실패한 스트림이 남긴 빈 자리 메시지는 먼저 제거한다.

#### Scenario: HTTP 오류
- **WHEN** API가 2xx가 아닌 상태 코드로 응답하면
- **THEN** "Error: HTTP <코드>: <본문(잘림)>" 어시스턴트 말풍선이 표시된다

### Requirement: 웹 페이지 읽기
10줄 이하 사용자 메시지에 `http(s)` URL이 포함되면 전송 전에 첫 번째 URL
1개의 페이지를 내려받아 본문 텍스트(HTML → 텍스트 변환, 최대 2만 자)를
추출하고 통합 첨부 카운터로 `ID<n>`을 부여한다. 미리보기 말풍선(og:image
썸네일 + ID + 도메인 + 본문 첫 줄)을 표시한다.

본문은 그 메시지가 마지막 메시지인 요청에만 `content` 끝에 덧붙고, 이후
요청부터는 해당 메시지 자리를 `[Page ID<n> (<도메인>) — mention "ID<n>"
to re-include]` 스텁으로 대체한다. 가져오기 실패 시 미리보기 말풍선에
간결한 오류("HTTP <코드>", "timeout", "network error", "no content",
"invalid URL")를 표시한다.

#### Scenario: 긴 붙여넣기 안의 URL
- **WHEN** 10줄 초과 붙여넣기 텍스트 안에 URL이 포함되어 있으면
- **THEN** 해당 URL을 가져오지 않고 붙여넣은 텍스트만 전송된다

### Requirement: 긴 붙여넣기 접기
사용자 메시지가 10줄을 초과하면 접힌 카드(문서 아이콘 + 첫 줄 한 줄
말줄임 + "붙여넣은 텍스트 · N줄")로 표시하고 More/Less로 펼친다. 접힘
라벨은 추론 말풍선과 같은 형식으로 ID를 오른쪽에 함께 표시한다
("More, ID<n>p"). 통합 첨부 카운터로 `ID<n>p`를 부여한다. 전문은 그
메시지가 마지막 메시지인 요청에만 `[Pasted text ID<n>p]` 태그와 함께
담고, 이후 요청부터는 `[Text ID<n>p (<첫 줄>) — mention "ID<n>p" to
re-include]` 스텁으로 대체한다.

#### Scenario: 긴 붙여넣기 카드
- **WHEN** 사용자가 10줄을 초과하는 텍스트를 붙여넣어 보내면
- **THEN** 접힌 카드로 표시되고 그 요청에만 `[Pasted text ID<n>p]` 태그와 함께 전문이 전송된다

#### Scenario: 접힘 라벨의 ID
- **WHEN** 접힌 붙여넣기 카드의 More/Less 라벨을 보면
- **THEN** ID<n>p가 라벨 오른쪽에("More, ID<n>p") 함께 표시된다

### Requirement: 첨부 ID 언급 재포함
마지막 사용자 메시지가 첨부 ID(예: "ID1", "ID2p")를 언급하면 해당 첨부의
전문을 그 요청에 다시 덧붙인다. 여러 ID는 모두 덧붙고 이미 포함된 첨부는
중복하지 않는다.

#### Scenario: 첨부 ID 재언급
- **WHEN** 마지막 사용자 메시지가 첨부 ID(예: "ID1")를 언급하면
- **THEN** 해당 첨부의 전문이 그 요청에 다시 덧붙여진다

### Requirement: 인라인 마크다운 표시
어시스턴트 답변 말풍선은 인라인 마크다운(굵게, 기울임, `코드 범위`, 링크)을
스타일로 렌더링하며 스트리밍 중에도 도착 즉시 반영한다. 인라인 수식
(`$…$`, `$$…$$`)은 유니코드 근사로 변환해 표시한다(그리스 문자,
합·적분 등 빈출 기호, 유니코드에 존재하는 하·첨자, `^\top`·`\frac`의
선형화). 변환할 수 없는 명령은 원문을 유지하고, 역슬래시·`^`·`_`가
없는 달러 구간은 수식이 아니라고 보아 그대로 둔다. 블록 요소(코드
펜스, 목록, 제목)는 스타일 없이 원문 텍스트로 표시한다. 취소선(`~~`)은
렌더링하지 않는다(기호는 소비되고 내용만 표시된다). 파싱이 실패한
답변은 원문 그대로 표시한다.

#### Scenario: 스트리밍 중 강조 렌더링
- **WHEN** 답변에 `**굵게**` 같은 인라인 마크다운이 포함되면
- **THEN** 기호 대신 스타일로 표시된다

#### Scenario: 취소선 미렌더링
- **WHEN** 답변에 `~~기호~~`가 줄바꿈을 포함해 나타나면
- **THEN** 어떤 줄에도 취소선이 그어지지 않고(기호는 소비됨) 다른
  인라인 스타일은 유지된다

#### Scenario: 인라인 수식 변환
- **WHEN** 답변에 `$f(x) = \sum_i v_i (k_i^\top x)$`가 포함되면
- **THEN** 유니코드 근사(Σ·첨자·ᵀ 등)로 변환되어 표시된다

#### Scenario: 통화 오인 방지
- **WHEN** 답변에 `$5 and $6`처럼 수식 기호 없는 달러 구간이 있으면
- **THEN** 변환 없이 원문 그대로 표시된다

### Requirement: YouTube 자막 읽기
URL이 YouTube 동영상(watch 또는 youtu.be)이면 페이지 본문 대신 자막
텍스트를 본문으로 사용한다. 자막은 수동 자막을 자동 생성보다 우선하고,
시스템 언어, 영어, 첫 번째 순으로 트랙을 고르며 최대 2만 자로 자른다.
자막을 얻을 수 없으면 페이지 메타데이터(og:title, og:description)를 본문으로
사용하고 본문 첫 줄에 "Video metadata (no captions): <제목>" 마커로
메타데이터 기반 요약임을 나타낸다. 메타데이터도 없으면 기존 실패
오류("no content", "network error" 등)로 미리보기에 표시한다. 미리보기
형식, 첨부 ID, 마지막 요청 전문 첨부와 이후 스텁 대체, URL 지시문 요약은
웹 페이지 읽기 요구사항을 그대로 따른다.

#### Scenario: YouTube URL 요약
- **WHEN** 자막이 있는 YouTube URL만 붙여넣어 보내면
- **THEN** 자막이 첨부되어 URL 지시문에 따라 요약으로 답한다

#### Scenario: 자막 없는 영상의 메타데이터 요약
- **WHEN** 자막이 없는 YouTube URL을 보내면
- **THEN** 메타데이터가 첨부되어 요약으로 답하고 본문 첫 줄에 메타데이터 기반임이 표시된다

#### Scenario: 메타데이터도 없는 영상
- **WHEN** 자막과 메타데이터 모두 없는 YouTube URL을 보내면
- **THEN** 가져오기 실패 오류 미리보기가 표시되고 대화는 계속된다

### Requirement: 붙여넣기 형식 제한
입력란에 붙여넣을 수 있는 것은 텍스트와, 현재 모델이 이미지 입력을
지원할 때는 이미지다. 이미지 입력 지원 판정은 모델명에 "flash"가
포함되는지로 한다(대소문자 무시). 10줄 이하 텍스트는 초안에 삽입한다.
10줄 초과 텍스트는 붙여넣는 즉시 별도의 붙여넣기 항목으로 승격되어(첫
줄과 줄 수 표시, 삭제·초안 되돌리기 가능) 입력란은 비워 둔다. 전송 시
이 항목이 본문이 되어 긴 붙여넣기 접기 규칙(`ID<n>p`)을 따르고, 초안에
입력이 남아 있으면 개행으로 이어 붙여 함께 전송한다. pasteboard에
이미지가 있고 문자열이 비었거나 경로 형태(절대 경로 + 이미지 확장자,
파일 존재는 요구하지 않음)일 때, 또는 문자열이 존재하는 이미지 파일의
경로일 때는 이미지 붙여넣기로 판정한다 — 이미지 데이터가 동반되면 그
데이터를 직접 쓴다. 지원 모델에서는 이미지 첨부로 승격되고, 미지원
모델에서는 거부되고 짧은 안내가 표시된다. 이미지와 함께 독립 텍스트가
있으면 텍스트만 취한다. 설정 섹션이 열려 있을 때는 이 제한을 적용하지
않는다.

#### Scenario: 긴 텍스트 붙여넣기
- **WHEN** 10줄을 초과하는 텍스트를 붙여넣으면
- **THEN** 붙여넣기 항목이 즉시 표시되고 입력란은 비어 있으며, 전송 시
  전문이 `ID<n>p` 첨부로 처리된다

#### Scenario: 이미지 붙여넣기 거부
- **WHEN** 이미지 입력을 지원하지 않는 모델을 쓰면서 텍스트 없이
  이미지만 붙여넣으면
- **THEN** 아무것도 삽입되지 않고 텍스트만 지원한다는 안내가 잠깐
  표시된다

#### Scenario: 지원 모델에서 이미지 승격
- **WHEN** 모델명에 "flash"가 포함된 상태에서 텍스트 없이 이미지만
  붙여넣으면
- **THEN** 이미지가 첨부 항목으로 승격되어 썸네일이 표시되고 입력란은
  비워 둔다

#### Scenario: 파일 경로 동반 이미지 붙여넣기
- **WHEN** 캡처 파일 등 이미지 데이터와 파일 경로 문자열이 함께
  붙여넣어지면
- **THEN** 경로가 입력란에 붙지 않고 이미지 붙여넣기로 처리된다(지원
  모델은 첨부 승격, 미지원 모델은 거부 안내)

#### Scenario: 경로 문자열만 있는 이미지 붙여넣기
- **WHEN** pasteboard에 이미지 파일의 경로 문자열만 들어 있으면
- **THEN** 경로가 입력란에 붙지 않고 이미지 붙여넣기로 처리된다

### Requirement: 응답 대기 표시
스트리밍이 진행 중이고 마지막 메시지가 어시스턴트 답변이 아니거나
어시스턴트 답변의 본문이 비어 있으면, 답변이 올 자리에 어시스턴트
말풍선과 같은 형태의 대기 표시(작은 스피너)를 전송 직후부터 표시한다.
추론만 도착한 동안에는 추론 말풍선 아래 답변 자리에 표시한다. 페이지
가져오기 중에는 스피너 옆에 "페이지 가져오는 중…" 문구를 함께 표시하고,
가져오기가 끝나면 문구만 빠진다. 첫 답변 델타가 도착하거나 스트림이
오류로 끝나면 대기 표시는 사라지고 실제 답변 또는 오류 표시로 이어진다.

#### Scenario: 첫 토큰 대기
- **WHEN** 사용자가 메시지를 보내고 첫 답변 델타가 아직 도착하지 않았으면
- **THEN** 답변 자리에 스피너 대기 표시가 나타나 있다

#### Scenario: 답변 시작
- **WHEN** 첫 답변 델타가 도착하면
- **THEN** 대기 표시가 사라지고 그 자리에서 실제 답변이 스트리밍된다

#### Scenario: 페이지 가져오기 중 대기
- **WHEN** URL 메시지 전송으로 페이지를 가져오는 중이면
- **THEN** 대기 말풍선에 스피너와 함께 가져오기 문구가 표시된다

#### Scenario: 추론 후 답변 대기
- **WHEN** 추론이 도착했지만 답변 본문의 첫 델타가 아직 도착하지 않았으면
- **THEN** 추론 말풍선 아래 답변 자리에 스피너 대기 표시가 나타나 있다

### Requirement: 이미지 첨부
이미지 첨부는 전송 시 긴 변이 1568px을 넘지 않도록 리사이즈한 JPEG
Base64 Data URL로 `image_url` content 파트에 실린다. 통합 첨부
카운터로 `ID<n>i`를 부여받고, 첨부된 사용자 말풍선에 썸네일이
표시된다. 이미지는 그 메시지가 마지막 메시지인 요청에만 실리고 이후
요청부터는 `[Image ID<n>i]` 스텁으로 대체하며, `ID<n>i`를 언급하면
해당 이미지가 재포함된다. 첨부 항목은 삭제할 수 있다.

#### Scenario: 이미지 전송
- **WHEN** 이미지 첨부와 함께 메시지를 보내면
- **THEN** 요청 content에 텍스트와 이미지 파트가 함께 실리고 말풍선에
  썸네일이 표시되며 `ID<n>i`가 부여된다

#### Scenario: 이미지 언급 재포함
- **WHEN** 이후 메시지에서 `ID<n>i`를 언급하면
- **THEN** 해당 이미지가 그 요청에 다시 실린다

### Requirement: 이미지 드롭
채팅 패널의 기록·입력 영역은 이미지 드롭 대상이다. 이미지 파일을
드롭하면 지원 모델에서는 이미지 첨부로 승격되고(썸네일 칩 표시),
미지원 모델에서는 거부 안내가 표시된다. 어떤 경우든 파일 경로가
입력란에 삽입되지 않는다.

#### Scenario: 이미지 파일 드롭
- **WHEN** 지원 모델 상태에서 이미지 파일을 패널에 드롭하면
- **THEN** 이미지가 첨부 항목으로 승격되고 경로는 입력란에 들어가지
  않는다

#### Scenario: 미지원 모델 드롭
- **WHEN** 미지원 모델 상태에서 이미지 파일을 드롭하면
- **THEN** 거부 안내가 표시되고 경로는 입력란에 들어가지 않는다
