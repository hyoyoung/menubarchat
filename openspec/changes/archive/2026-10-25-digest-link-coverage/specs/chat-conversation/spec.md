# Spec Delta

## MODIFIED Requirements

### Requirement: 웹 페이지 읽기
10줄 이하 사용자 메시지(커스텀 슬래시 명령으로 전개된 메시지는 길이와
무관하게 포함)에 `http(s)` URL이 포함되면 전송 전에 페이지를
내려받아 본문 텍스트(HTML → 텍스트 변환, 페이지당 최대 2만 자)를
추출한다. 변환은 마크업·스타일·스크립트 블록을 제거한 뒤 남은 텍스트를
대상으로 하며(길이 절단은 블록 제거 후에만 적용), 사람 눈에 보이지
않는 요소 — 인라인 스타일의 `display:none`·`visibility:hidden`·
`opacity:0`·font-size 9px 미만·Tailwind `text-[0-8]px`·`hidden`·
`aria-hidden` — 는 정적 변환 전에 제거한다. 렌더링 추출에서는 계산
스타일 기준으로 font-size 9px 미만·숨김 노드를 DOM에서 제거한 뒤 본문을
읽는다. 결과가 내비게이션·장식
조각 수준으로 빈약하면(JS 의존 페이지) 스크립트를 실행하는 렌더링
추출(최대 3초 대기)로 대체하고, 그 결과가 충분한 본문일 때만 채택한다.
본문 텍스트와 함께 페이지의 앵커 (제목, URL) 목록을 수집한다 — 정적
HTML과 렌더링 추출의 DOM 양쪽에서, http(s)만, 상대 URL은 페이지 URL로
해석, 프래그먼트(`#`) 링크 제외, href 기준 중복 제거, 페이지당 상한
80개. 일반 사용자 메시지는 첫 번째 URL 1개만 가져오고 통합 첨부
카운터로 `ID<n>`을 부여하며 미리보기 말풍선(og:image 썸네일 + ID +
도메인 + 본문 첫 줄)을 표시한다. 커스텀 슬래시 명령으로 전개된 메시지는
**전개 프롬프트 자체의 URL 전부**(이력 주입 등으로 메시지에 덧붙은 URL은
제외)를 가져온다 — 최대 10개(11번째부터는 가져오지 않고 무시),
동시에 2개까지만 병렬로 내려받는다(완료되는 대로 다음 URL 투입) — 그리고
페이지 묶음 전체에 통합 카운터로 **1개의 `ID<n>`**을 부여한다(개별
페이지 ID는 없음). 명령 메시지의 미리보기는 썸네일 없이 `ID · N sources`
머리와 도메인 목록을 담은 단일 카드이고, 가져오기 실패한 페이지는 해당
줄에 간결한 오류("HTTP <코드>", "timeout", "network error", "no
content", "invalid URL")를 함께 표시한다. 일반 메시지에서 실패 시에는
해당 페이지의 미리보기 말풍선에 간결한 오류를 표시한다.

본문은 그 메시지가 마지막 메시지인 요청에만 덧붙는다. 일반 메시지의
단일 페이지 첨부는 전문으로 실는다(기존 방식). 명령 전개 메시지의 다중
페이지 첨부는 페이지당 앞 4천 자 발췌로 실고 메시지 첨부 합계는 2만 자
상한(초과 시 페이지별 비례 축소)으로 제한하며, 발췌 뒤에 그 페이지의
앵커 목록("Links:" 형식)을 함께 실는다. 전문은 보관하며, 이후
요청부터는 해당 메시지 자리를 일반 메시지는 `[Page ID<n> (<도메인>)]`,
명령 메시지는 묶음 ID 1줄 스텁으로 대체한다.

#### Scenario: 긴 붙여넣기 안의 URL
- **WHEN** 10줄 초과 붙여넣기 텍스트 안에 URL이 포함되어 있으면
- **THEN** 해당 URL을 가져오지 않고 붙여넣은 텍스트만 전송된다

#### Scenario: 일반 메시지는 첫 URL만
- **WHEN** 일반 사용자 메시지에 여러 URL이 포함되어 전송되면
- **THEN** 첫 번째 URL 1개만 fetch되고 나머지 URL은 텍스트로 남는다

#### Scenario: 명령 전개 메시지의 다중 URL
- **WHEN** 커스텀 슬래시 명령으로 전개된 메시지에 여러 URL이 포함되어
  전송되면
- **THEN** 각 URL의 페이지가 내려받아지고(동시 2개) 묶음에 ID 1개가
  부여되며, 미리보기는 `ID · N sources` 머리 + 도메인 목록의 단일
  카드로 표시되고, 마지막 메시지 첨부는 페이지당 발췌 + 앵커 목록으로
  합계 상한 내에 실린다

#### Scenario: 명령 목록 카드의 오류
- **WHEN** 명령 실행 중 일부 페이지 가져오기가 실패하면
- **THEN** 목록 카드의 해당 줄에 간결한 오류가 표시된다

#### Scenario: JS 의존 페이지는 렌더링 추출
- **WHEN** 정적 텍스트가 내비게이션 수준으로 빈약한 페이지(예: 뉴스
  포털 홈)를 가져오면
- **THEN** 스크립트를 실행하는 렌더링 추출로 전환되어 기사 제목·본문
  텍스트가 추출되고, 발췌에는 크롬 조각 대신 실제 내용이 담긴다

#### Scenario: 이전 다이제스트 주입 후에도 명령은 fetch
- **WHEN** `{previous}` 주입으로 명령 전개 메시지가 10줄을 초과하면
- **THEN** 붙여넣기로 분류되지 않고 URL fetch가 정상 수행된다

#### Scenario: 이력 주입분 URL은 fetch하지 않음
- **WHEN** `{previous}`로 주입된 이전 다이제스트에 URL이 포함되어 있으면
- **THEN** fetch 대상은 전개 프롬프트 자체의 URL뿐이며 이력의 URL은
  가져오지 않는다

#### Scenario: 앵커 수집
- **WHEN** 명령 메시지의 페이지를 가져오면
- **THEN** 각 페이지의 http(s) 앵커 (제목, URL) 목록이 상한 80개까지
  수집되어 발췌 뒤 "Links:"로 첨부된다

#### Scenario: 숨김 텍스트는 추출에서 제외
- **WHEN** 페이지에 `display:none`·`opacity:0`·9px 미만 글씨 등 눈에
  보이지 않는 요소가 포함되어 있으면
- **THEN** 정적·렌더링 추출 모두 해당 요소의 텍스트를 본문에서 제외한다
