# Spec Delta

## MODIFIED Requirements

### Requirement: 뉴스 다이제스트 이력
뉴스 명령(`/news`)의 응답이 완료되면 그 다이제스트 텍스트와 타임스탬프를
Application Support의 JSON 파일(최근 5개 항목의 링)에 저장한다 — 단,
그 명령 메시지에 가져오기 성공한 페이지(오류 없음)가 1개 이상 있을 때만
저장하며 fetch 없이 응답한 거절·안내 답변은 저장하지 않는다. 다이제스트
전개 시 이력을 재사용하기 전에 **24시간보다 오래된 항목은 제거하고 파일을
다시 쓴다**. 전개된 뉴스 프롬프트의 `{previous}`는 24시간 내 직전 최대
2개 다이제스트의 **평문**으로 치환된다 — 강조 기호(`**`·`*`)는 제거하고
`[제목](URL)`은 제목 텍스트로 풀어서 주입한다(이력은 이미 다룬 기사
식별용이지 서식 견본이 아니다). 항목이 없으면 "none"이 주입되며, 프롬프트은
이전 다이제스트에 이미 다룬 기사를 반복하지 않도록 지시한다. 표시는
무변경.

#### Scenario: 이전 다이제스트 주입
- **WHEN** 24시간 내 이전 실행이 있는 상태에서 `/news`를 실행하면
- **THEN** 전개 프롬프트에 직전 다이제스트가 포함되고 새 다이제스트는
  이미 다룬 기사를 반복하지 않는다

#### Scenario: 24시간 경과 항목 만료
- **WHEN** 이력 파일에 24시간보다 오래된 항목이 있고 다이제스트 전개가
  이력을 재사용하면
- **THEN** 해당 항목은 제거되어 파일이 다시 쓰이고 치환·주입 대상에서도
  빠진다

#### Scenario: 응답 저장
- **WHEN** 뉴스 명령의 응답 스트림이 완료되고 가져오기 성공한 페이지가
  있으면
- **THEN** 그 다이제스트가 이력 링(최근 5개)에 추가된다

#### Scenario: fetch 실패 실행은 저장 안 함
- **WHEN** fetch가 실패하거나 건너뛰어 요청에 성공한 페이지가 없어 모델이
  거절·안내로 답하면
- **THEN** 그 응답은 이력에 저장되지 않는다

#### Scenario: 첫 실행
- **WHEN** 이력이 비어 있을 때 `/news`를 실행하면
- **THEN** `{previous}`는 "none"으로 치환되어 정상 동작한다

#### Scenario: 주입은 평문
- **WHEN** 이전 다이제스트에 강조 기호·링크 마크업이 포함되어 있어도
- **THEN** `{previous}`로 주입되는 텍스트는 기호 없는 평문(링크는 제목만)
  이며 새 다이제스트의 서식은 프롬프트 지시만 따른다
