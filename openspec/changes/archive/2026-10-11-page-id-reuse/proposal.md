# 제안: 페이지 본문 1회 전송과 ID 기반 재참조

## 왜

웹 페이지 본문(최대 2만 자 ≈ 5천 토큰)이 대화가 끝날 때까지 매 요청마다
재전송돼 입력 토큰이 계속 누적된다. 본문은 첫 요청에만 보내고, 이후에는
ID 언급 시에만 다시 포함하면 대부분의 턴에서 비용이 스텁 수준으로 줄면서
필요할 때 기억을 되살릴 수 있다.

## 무엇을

- 가져온 페이지마다 세션 증가 ID(`ID1`, `ID2`, …)를 부여하고 미리보기
  카드에 도메인과 함께 표시한다.
- 페이지 본문은 그 페이지가 붙은 사용자 메시지가 **마지막 메시지인 요청에만**
  포함한다. 이후 요청부터는 `[Page ID1 (example.com) — mention "ID1" to
  re-include]` 스텁으로 대체한다.
- 마지막 사용자 메시지 본문에 `ID<n>` 언급이 있으면, 해당 ID의 페이지
  본문을 그 요청에 다시 포함한다(중복 ID는 한 번만).
- ID와 페이지는 메모리 상태로만 유지한다(대화 자체가 휘발성이므로).
