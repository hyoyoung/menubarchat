# Spec Delta

## MODIFIED Requirements

### Requirement: 스트리밍 표시
SSE로 응답을 스트리밍한다. `reasoning_content` 델타는 답변 위의 작은
글씨 회색 말풍선에, `content` 델타는 기본 크기 답변 말풍선에 덧붙이며
도착하는 즉시 반영한다. 최신 메시지로의 자동 스크롤은 팔로우 상태에서만
일어난다: 사용자가 위로 스크롤하면 팔로우가 끊겨 스크롤 위치가 유지되고,
뷰포트가 맨 아래에 도달하거나 사용자가 메시지를 전송하면 재개된다.
팔로우가 끊긴 상태에서 재개되는 순간 즉시 고정점으로 스냅한다(재게
판정의 관용 간격을 흡수해 이후 핀과 앵커를 일치시킨다).
바닥 팔로우의 고정점은 기록의 끝 전체다 — 대기 표시(스피너·문구 행)가
표시되는 동안에는 그 행을 끝으로 삼아 고정하며, 그렇지 않으면 마지막
메시지의 아래를 끝으로 삼는다. 팔로우가 끊긴 동안에만 기록 하단에 떠
있는 점프 버튼이 표시되며 누르면 즉시 맨 아래로 이동해 팔로우를 재개한다.
스트림은 `[DONE]` 데이터 라인에서 끝난다.

#### Scenario: 추론과 답변 분리 표시
- **WHEN** 델타에 `reasoning_content`와 `content`가 번갈아 도착하면
- **THEN** 추론은 작은 글씨 회색 말풍선에, 답변은 기본 크기 말풍선에 즉시 덧붙여진다

#### Scenario: 스크롤 위치 유지
- **WHEN** 스트리밍 중 사용자가 위로 스크롤하면
- **THEN** 새 델타가 도착해도 화면은 끌려가지 않고 점프 버튼이 나타난다

#### Scenario: 점프 버튼으로 복귀
- **WHEN** 팔로우가 끊긴 상태에서 점프 버튼을 누르면
- **THEN** 즉시 맨 아래로 이동하고 팔로우가 재개된다

#### Scenario: 대기 표시까지 바닥 고정
- **WHEN** 대기 표시(스피너)가 표시되는 동안 사용자가 맨 아래로 스크롤해
  팔로우가 재개되면
- **THEN** 새 델타가 도착해도 대기 표시가 화면에 남고 뷰가 위로 점프하지
  않는다

#### Scenario: 재개 시 즉시 스냅
- **WHEN** 팔로우가 끊긴 상태에서 사용자가 바닥 근처까지 스크롤해 팔로우가
  재개되면
- **THEN** 재개 즉시 고정점으로 스냅해 이후 델타 핀과 앵커가 일치하므로
  화면이 위로 튀어 보이지 않는다
