# Spec Delta

## MODIFIED Requirements

### Requirement: 웹 페이지 읽기
10줄 이하 사용자 메시지에 `http(s)` URL이 포함되면 전송 전에 페이지를
내려받아 본문 텍스트(HTML → 텍스트 변환, 페이지당 최대 2만 자)를
추출한다. 일반 사용자 메시지는 첫 번째 URL 1개만 가져오고 통합 첨부
카운터로 `ID<n>`을 부여하며 미리보기 말풍선(og:image 썸네일 + ID +
도메인 + 본문 첫 줄)을 표시한다. 커스텀 슬래시 명령으로 전개된 메시지는
URL 전부를 가져온다 — 최대 10개(11번째부터는 가져오지 않고 무시),
동시에 2개까지만 병렬로 내려받는다(완료되는 대로 다음 URL 투입) — 그리고
페이지 묶음 전체에 통합 카운터로 **1개의 `ID<n>`**을 부여한다(개별
페이지 ID는 없음). 명령 메시지의 미리보기는 썸네일 없이 `ID · N sources`
머리와 도메인 목록을 담은 단일 카드이고, 가져오기 실패한 페이지는 해당
줄에 간결한 오류("HTTP <코드>", "timeout", "network error", "no
content", "invalid URL")를 함께 표시한다. 일반 메시지에서 실패 시에는
해당 페이지의 미리보기 말풍선에 간결한 오류를 표시한다.

본문은 그 메시지가 마지막 메시지인 요청에만 덧붙는다. 일반 메시지의
단일 페이지 첨부는 전문으로 실는다(기존 방식). 명령 전개 메시지의 다중
페이지 첨부는 페이지당 앞 4천 자 발췌로 실고 메시지 첨부 합계는 2만 자
상한(초과 시 페이지별 비례 축소)으로 제한한다. 전문은 보관하며, 이후
요청부터는 해당 메시지 자리를 일반 메시지는 `[Page ID<n> (<도메인>)]`,
명령 메시지는 묶음 ID 1줄 스텁으로 대체한다.

#### Scenario: 긴 붙여넣기 안의 URL
- **WHEN** 10줄 초과 붙여넣기 텍스트 안에 URL이 포함되어 있으면
- **THEN** 해당 URL을 가져오지 않고 붙여넣은 텍스트만 전송된다

#### Scenario: 일반 메시지는 첫 URL만
- **WHEN** 일반 사용자 메시지에 여러 URL이 포함되어 전송되면
- **THEN** 첫 번째 URL 1개만 fetch되고 나머지 URL은 텍스트로 남는다

#### Scenario: 명령 전개 메시지의 다중 URL
- **WHEN** 커스텀 슬래시 명령으로 전개된 메시지에 여러 URL이 포함되어
  전송되면
- **THEN** 각 URL의 페이지가 내려받아지고(동시 2개) 묶음에 ID 1개가
  부여되며, 미리보기는 `ID · N sources` 머리 + 도메인 목록의 단일
  카드로 표시되고, 마지막 메시지 첨부는 페이지당 발췌로 합계 상한 내에
  실린다

#### Scenario: 명령 목록 카드의 오류
- **WHEN** 명령 실행 중 일부 페이지 가져오기가 실패하면
- **THEN** 목록 카드의 해당 줄에 간결한 오류가 표시된다

### Requirement: 첨부 ID 언급 재포함
마지막 사용자 메시지가 첨부 ID(예: "ID1", "ID2p")를 언급하면 해당 첨부의
전문을 그 요청에 다시 덧붙인다. 페이지(ID<n>)의 경우 요약 첨부가 발췌였더라도 재포함은 전문으로 실는다. 여러 ID는 모두 덧붙고 이미 포함된 첨부는
중복하지 않는다. 명령 메시지의 묶음 ID는 참조 표시일 뿐 언급 재포함의
대상이 아니다 — 심화가 필요하면 해당 URL을 직접 다시 보낸다.

#### Scenario: 첨부 ID 재언급
- **WHEN** 마지막 사용자 메시지가 첨부 ID(예: "ID1")를 언급하면
- **THEN** 해당 첨부의 전문이 그 요청에 다시 덧붙여진다

#### Scenario: 묶음 ID 언급은 재포함하지 않음
- **WHEN** 마지막 사용자 메시지가 명령 묶음 ID를 언급하면
- **THEN** 재포함 없이 원문 텍스트로만 전달된다
